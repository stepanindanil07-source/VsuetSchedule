# Расписание ВГУИТ: мобильное приложение (Android, без сервера)

Приложение само скачивает файлы расписания с vsuet.ru, разбирает их на устройстве, сохраняет в SQLite и дальше работает без интернета.
Backend, PostgreSQL и REST не используются. Ядро (парсеры, сборка набора, календарь, схема SQLite) лежит в [../core-ts](../core-ts/README.md) и
подключается как исходники.

Стек: Expo SDK 58, React Native 0.88 (Hermes), TypeScript, React Navigation, Zustand, expo-sqlite, expo-file-system.

## Запуск

```bash
cd core-ts && npm ci          # зависимости ядра (SheetJS)
cd ../mobile && npm ci
npx tsc --noEmit              # типы
npx jest                      # тесты
npx expo prebuild --platform android --no-install
npx expo run:android --variant release   # сборка и установка на эмулятор или телефон (нужны Android SDK и JDK)
```

Каталог `android/` не хранится в репозитории: он создаётся командой `expo prebuild` из `app.json` и config plugin `plugins/withNetworkSecurityConfig.js`.

## Устройство

| Каталог | Что делает |
|---|---|
| `src/sync` | загрузка файлов (условные запросы, повторы, тайм-ауты), копии файлов, `SyncService`: проверить, разобрать, собрать набор, подменить |
| `src/storage` | интерфейс `Db`, `AppRepo` (постоянная app.db: настройки, файлы, журнал, диагностика), `DatasetManager` (база набора, две ячейки A/B) |
| `src/domain` | даты, тип недели (календарь набора или ручная настройка), отбор занятий на день |
| `src/state` | хранилище Zustand: фазы приложения, выбранная группа, синхронизация |
| `src/features` | экраны: первый запуск, выбор группы, Сегодня, Расписание, Настройки, Диагностика |
| `src/config/appConfig.ts` | интервал проверки, тайм-ауты, повторы; реестр источников и семестр берутся из ядра |

### Как обновляется расписание

1. Каждый из 8 файлов запрашивается условным запросом (`If-None-Match`, `If-Modified-Since`). Ответ 304 означает «не менялся».
2. Скачанный файл проверяется по началу (Excel, а не страница ошибки). Нет сети или файл плохой: берётся сохранённая копия.
3. Если контрольные суммы файлов и версии парсеров те же, что в рабочем наборе, ничего не разбирается.
4. Иначе файлы разбираются парсерами по `parserId` источника, ядро собирает набор целиком и проверяет его (обязательные источники, период, дубли, резкое падение числа занятий).
5. Набор записывается в НЕРАБОЧУЮ ячейку (`dataset-a.db` / `dataset-b.db`), проверяется (`quick_check`, число строк) и становится рабочим одной записью в app.db.
   Любая ошибка до этого момента оставляет прежнее расписание. Выбранная группа хранится по естественному ключу `подразделение/код` и переживает обновления.
6. Файл становится рабочей копией только после успешного разбора; журнал и сообщения парсеров попадают в диагностику (хранятся последние 10 синхронизаций).

Автоматическая проверка идёт при запуске и при возврате в приложение, не чаще раза в 6 часов; кнопка «Проверить обновления» интервал не учитывает.

### Числитель и знаменатель

Чётность ISO-недели не используется. Тип недели берётся из календаря набора (якорь введён вручную в реестре источников) или из ручной настройки
пользователя («сейчас числитель/знаменатель»: дальше недели чередуются от выбранной). Нет ни того, ни другого: тип неизвестен, занятия «только числитель»
и «только знаменатель» показываются с пометкой, а экран просит выбрать тип недели.

## Ограничения

- Каждый семестр (период, якорь числителя, привязка файлов без семестра) и любое изменение адресов или формата файлов требуют нового выпуска приложения.
- Подключено 8 из 15 файлов с официальной страницы; остальные 7 числятся как пробелы полноты, это видно в настройках.
- Разбор идёт на потоке JavaScript; между файлами интерфейс получает возможность перерисоваться.
- Сайт vsuet.ru подписан цепочкой, оканчивающейся корнем GlobalSign Root R46. Для устройств без этого корня добавлен якорь доверия только для vsuet.ru
  (`assets/certs`, `plugins/withNetworkSecurityConfig.js`).
