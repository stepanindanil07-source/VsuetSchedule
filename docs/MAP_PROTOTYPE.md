# Прототип плана корпуса (демо)

Дата: 2026-11-24. Назначение: оценить трудоёмкость и возможности «своей карты» внутри приложения: показать аудиторию из расписания
на плане этажа и построить маршрут по коридорам. Это **демонстрация**, не готовая фича.

## Что сделано

- Экран «План» (`mobile/src/features/plan`): план этажа, подсветка аудитории, масштаб и сдвиг (одним и двумя пальцами, кнопки), указание
  «я здесь» нажатием на комнату и маршрут до аудитории, переход к аудитории и к целому этажу.
- Кнопка «На плане ›» в карточке занятия, если аудитория из расписания найдена на плане.
- Данные (`mobile/src/plan`): формат плана (комнаты-многоугольники, оси коридоров, лестницы), поиск аудитории по номеру, маршрут (кратчайший путь по сетке узлов,
  построенной по осям коридоров), тесты (16 тестов в `tests/plan*.test.*`).
- Демонстрационный этаж: первый этаж главного корпуса, ~70 помещений, схематично.

## Происхождение данных демо-плана

Расположение номеров аудиторий взято по снимку карты 2ГИС, которым владелец проекта поделился для оценки трудоёмкости; сами рисунки и данные 2ГИС
в приложение не копировались (комнаты это прямоугольники вокруг подписей, коридоры нарисованы по догадке, входов нет). Владелец проекта сообщил, что
использование данных вуза согласовано с управлением университета. Согласование покрывает данные университета, а не карту 2ГИС, поэтому **для выпуска план
нужно заменить планами университета** (поэтажные планы или схемы эвакуации). Формат данных остаётся тем же.

## Что видно из демо

- Нумерация неоднородна: трёхзначные номера (первая цифра этаж), номера с нулём (`017`), одно- и двузначные (`17`, `12`), номера с буквой (`016а`).
  `17` и `017` это разные комнаты. В расписании встречается `9`, на плане `09`: приложение ищет точное совпадение, а при его отсутствии без ведущих нулей и помечает
  результат как вероятный.
- Один номер может быть у двух помещений (`125`, `116` на плане дважды): подсвечиваются оба.
- Номера из расписания без корпуса. Сейчас размечен один этаж, поэтому корпус не угадывается. При нескольких корпусах нужна таблица «аудитория → корпус».
- Внутри здания нет GPS: маршрут это схема от выбранной комнаты, а не навигатор.

## Трудоёмкость (оценка, не измерение)

- Экран и поиск: сделаны. Каждый новый этаж это только данные.
- Разметка одного этажа вручную: в демо комнаты заданы таблицами по рядам; для настоящих планов нужен инструмент разметки (кликать по углам комнат поверх
  картинки, вводить номера, рисовать оси коридоров) и план университета в приличном качестве. Инструмент ещё не написан.
- Переходы между этажами (лестницы и лифты) в маршруте не реализованы: в демо один этаж.

## Полный план по снимку (локально, в git не хранится)

По запросу владельца проекта контур и помещения извлечены из снимка карты автоматически: `mobile/tools/plan-extract/extract.py` (контур здания, все помещения
включая безымянные, проходимые клетки коридоров; только numpy) и `to_ts.py` (файл данных). Результат лежит в `mobile/src/plan/generated/mainFloor1.ts`,
**каталог в `.gitignore`**: это производная от данных 2ГИС, а репозиторий публичный. Приложение берёт сгенерированный план, если файл есть (`activePlan.ts`),
иначе схематичный демо-план из репозитория; тесты `generatedPlan.test.ts` выполняются только при наличии файла.

Что умеет полный план: контур с внутренними дворами, 87 помещений (66 с номерами или названиями), лестницы, маршрут по проходимым клеткам со спрямлением пути.
Северо-восточное крыло (аудитории выше 145 на плане: 01–031 и рядом) помечено `access: UPPER_FLOOR`: на первом этаже туда нет прохода, маршрут не строится, экран объясняет,
что попасть можно только со 2 этажа (по указанию владельца проекта).

Ограничения: границы комнат взяты с 3D-вида снимка (перспектива), слипшиеся комнаты делятся по ближайшей подписи, узкие проходы (нижнее левое крыло) дорисованы вручную,
входов в здание нет, остальных этажей нет. Библиотека, читальный зал и блок «ВГУИТ» заданы вручную.

## Что осталось до выпуска

1. Планы университета и разрешение на публикацию в приложении.
2. Инструмент разметки; разметка остальных этажей и корпусов.
3. Таблица «аудитория → корпус», этажи, переходы между ними, входы в здания.
4. Проверка на устройствах разных размеров; доступность (подписи, контраст).
