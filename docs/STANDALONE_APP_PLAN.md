# Автономное мобильное приложение без backend: оценка и план

Статус: **на согласовании.** Дата 2026-11-23. Основание: новое ТЗ (приложение само скачивает Excel с vsuet.ru, разбирает, хранит в SQLite).
Что проверено, а что только гипотеза, помечено явно.

## 1. Что я проверил сейчас (факты)

| Проверка | Результат |
|---|---|
| React Native-проект на этом компьютере | **не найден.** Команда клиента работает в другом месте. Есть Node 24 и npm, Android SDK нет |
| Условные запросы к vsuet.ru | **работают:** у файлов есть `ETag` и `Last-Modified`, на `If-Modified-Since` сайт отвечает `304` (проверено на 3 файлах). Проверка обновления дёшево, без скачивания |
| Цепочка TLS-сертификатов | сервер присылает 2 сертификата (`*.vsuet.ru` и промежуточный `GlobalSign GCC R46 DV TLS CA 2025`), цепочка заканчивается корнем **GlobalSign Root R46**. С обычным набором CA без этого корня проверка не проходит. **Риск: часть Android-устройств может не доверять сайту** (какие именно версии, я не проверял) |
| Размер источников | 8 подключённых файлов около 1,3 МБ; итоговый набор 195 КБ в сжатом виде, 7285 занятий (измерено на живых данных) |
| Файл `1_kurs(1).xls` из ТЗ | в проекте нет; используется `1_kurs.xls` с сайта |

## 2. Что переходит из backend в новый проект

Backend не пропадает: он становится **эталоном и источником знаний**.

1. **Тестовый эталон (самое ценное).** Java-парсеры уже разбирают все 8 реальных файлов. Их результат (занятия, группы, диагностика)
   выгружается в JSON, и TypeScript-парсеры проверяются на совпадение с ним. Это снимает главный риск переноса: «разобрали иначе».
2. **Реальные файлы** как тестовые материалы (8 файлов, около 1,3 МБ).
3. **Знания о форматах** (в виде документа `FORMATS.md`, который нужно написать): геометрия объединённых ячеек, скрытые столбцы и
   строки (в СПО скрыты «мёртвые» группы), день недели и дата у заочки, курс по коду группы, привязка семестра у файлов без семестра
   или с ошибкой (`eiu.xlsx`), подгруппы по тексту, строгие правила отказа.
4. **Реестр источников**: 15 файлов на официальной странице, 8 подключены (`SOURCE_REGISTRY.md`).
5. **Тестовые сценарии**: 378 тестов становятся спецификацией для TypeScript-версий.
6. **Каноническая модель**: почти один в один перекладывается в `ScheduleEntry` из нового ТЗ (в нём даже поля те же).

Что **не нужно** (останется в репозитории backend как история): сервер, PostgreSQL, REST, развёртывание, административное API, план
серверного Dataset.

## 3. Новые риски, которые Java-сервер скрывал

1. **Доверие TLS на Android** (см. выше). Решение: добавить корневой сертификат GlobalSign R46 в `network_security_config` приложения
   как дополнительный якорь доверия для `vsuet.ru`. Нужна проверка на реальных устройствах (Android 8–13).
2. **Каждый семестр нужен новый релиз приложения** (или удалённая конфигурация). Причины: якорь числителя/знаменателя нигде не публикуется
   в машинном виде, `eiu.xlsx` приходится привязывать к семестру вручную (в тексте файла ошибка), у СПО 2–4 курсов и заочки семестра в файле нет,
   реестр URL может меняться. Варианты: (а) релиз на семестр; (б) небольшой статический JSON с конфигурацией семестра на GitHub Pages
   с запасной копией в приложении (это уже внешняя зависимость, а не «только официальные источники»); (в) только ручной выбор типа недели.
3. **Нет видимости ошибок «в поле».** Если на телефоне студента парсер упал, мы об этом не узнаем. Нужна пользовательская кнопка «отправить
   диагностику» (почта, мессенджер) либо согласие на анонимную отправку (это снова сервер).
4. **Исправления парсера доставляются только релизом.** На сервере правка действовала сразу для всех.
5. **Нагрузка на сайт университета.** Все установки ходят на `vsuet.ru` напрямую. Смягчение: условные запросы (поддерживаются),
   минимальный интервал проверки (например, раз в 6–12 часов), случайная задержка, ограничение параллельности. Сайт при этом
   нестабилен (я видел зависания соединения): нужны тайм-ауты, повторы, откат на последнюю рабочую базу.
6. **Производительность разбора на телефоне.** Не измерена. Файлы небольшие (до 400 КБ), но JS-движок Hermes и память слабых Android-устройств
   могут сделать разбор секундами. Нужен замер на реальном устройстве; тяжёлое вычисление не должно блокировать интерфейс.
7. **Устойчивость выбранной группы.** Числовые идентификаторы групп теперь создаются на устройстве и могут меняться между сборками набора.
   Выбранную группу нужно хранить по естественному ключу (подразделение + код группы), а не по числовому id.

## 4. Библиотеки для Excel (гипотезы, требуют проверки)

Единственная известная мне чисто-JS библиотека, умеющая и `.xls`, и `.xlsx`, это **SheetJS (`xlsx`)**. Гипотезы, которые нужно подтвердить
пробным запуском на реальных файлах (Node), а затем на устройстве:
- читает все 8 файлов, включая `.xls` с кириллицей (может понадобиться таблица кодовых страниц);
- отдаёт объединённые диапазоны (`!merges`), скрытые столбцы и строки, текст ячеек;
- оговорка: пакет `xlsx` на npm давно не обновляется и содержит известные уязвимости; актуальные версии распространяются с сайта
  SheetJS (CDN), а не через npm. Нужно выбрать версию и способ установки.
Альтернативы (ExcelJS, read-excel-file и т.п.) читают только `.xlsx`, так что для СПО не подходят.

## 5. Предлагаемое разделение работы

Парсеры, каноническая модель, DatasetBuilder, валидация и календарь **не зависят от React Native**: байты файла на входе, занятия на выходе.
Поэтому предлагается **TypeScript-ядро без зависимостей от RN** (в отдельном пакете, тестируется в Node/Jest на реальных файлах), которое
команда клиента подключает в приложение. Работу, требующую телефона (загрузка файлов, SQLite, фоновые задачи, интерфейс, замер времени,
проверка TLS), выполняет команда клиента или я при наличии проекта и устройства.

Структура ядра следует вашему ТЗ: `parsers/{common,fuits,spo,zao}`, `core/{parser,dataset,validation,calendar}`, порты (интерфейсы)
для файловой системы, HTTP и SQLite, которые реализует приложение.

## 6. Этапы

0. **Решения** (раздел 7) и разрешение на пробный запуск SheetJS.
1. **Исследование (Node):** SheetJS на всех 8 файлах; эталонная выгрузка из Java-парсеров; замеры времени и памяти в Node; документ `FORMATS.md`.

   синхронизация, первый сквозной прототип: скачать `uits.xlsx` → разобрать → SQLite → показать без интернета.

6. **Интерфейс** (Сегодня, Расписание, Настройки) и замеры на устройстве.
